# Accessibility acceptance checklist

- Keyboard navigation reaches all actions and menus in logical order.
- Focus indicators remain visible and are not obscured by sticky elements.
- Dialogs trap focus while open and restore focus on close.
- Inputs have labels; validation errors are programmatically associated.
- Statuses include text/icons, not color alone.
- Motion respects prefers-reduced-motion.
- 200% text zoom does not hide primary actions.
- Mobile targets are approximately 44×44 CSS pixels where practical.
- Tables have headers and responsive alternatives.
- Chat announces assistant/tool status updates without continuously interrupting reading.
